## 经验反思

### 文件写入最佳实践
1. **首选**: `write_file` 工具（简单场景）
2. **备选**: Python脚本文件（复杂内容）
   ```python
   # 写入脚本
   with open('script.py', 'w', encoding='utf-8') as f:
       f.write(script_content)
   # 执行脚本
   ```
3. **最后**: PowerShell `[System.IO.File]::WriteAllText()`

### 大文件处理策略
- 将大型HTML/代码分段写入
- 或使用Python脚本分步生成
- 避免单行命令传递大量内容

### 工具使用陷阱与规避
1. **`write_file` 参数顺序问题**: `file_path` 和 `content` 必须按命名参数传，仅传 `content` 会报 `missing required positional argument: 'file_path'`
2. **`write_file` 内容截断**: 当内容过大（>15-20KB）时，write_file可能截断文件。**解决方案**: 
   - 分两次写入（先写基础结构，再用 edit_file 追加JS）
   - 或用 Python 脚本生成完整文件
   - 验证文件末尾的完整性
3. **`edit_file` 的全局替换风险**: 使用通用HTML片段（如 `<span`）作为 old_text 会导致所有匹配都被替换，破坏文件结构。**解决方案**: 
   - 使用足够独特/完整的片段作为 old_text
   - 优先引用包含id/class等唯一标识的代码块
   - 替换后立即验证文件完整性
4. **模板字面量中的转义问题**: JavaScript 反引号模板字符串包含 `${}` 时要小心嵌套，多层嵌套最好用字符串拼接代替

### 大文件Python追加策略（本轮经验）
当需要在已有HTML文件末尾追加大量JS代码时：
1. 将追加内容拆分成多个Python脚本（wv4_p1.py, wv4_p2.py, ...）
2. 每个脚本用 `with open(path, 'a', encoding='utf-8')` 追加写入
3. 在Python的 `f.write("""...""")` 中处理JS转义：
   - Python `"""..."""` 中的 `\\'` → 文件 `\'` → JS中表示 `'` （单引号转义）
   - Python `"""..."""` 中的 `\\\\'` → 文件 `\\'` → JS中表示 `\'` （反斜杠+单引号）
   - **关键陷阱**: JS模板字符串中的转义需要仔细数反斜杠层数
4. 每次追加后验证：检查文件末尾是否完整、标签数是否匹配

### `render()` 函数优先级陷阱
- **错误**: 先检查 `phase` 再检查 `curProj` → 导致总览页点项目卡片无法进入工作区
- **正确**:
  ```javascript
  if(curProj){renderProject();return;}  // 先检查curProj
  if(phase==='overview'){renderOverview();return;}
  ```
- **经验**: 当多个状态变量共存时，优先级顺序直接影响UI流程。`curProj` 是最具体的状态（正在查看某个项目），应首先处理。

### 动态Tab切换的常见错误
- 错误：Tab按钮调用 `renderProjectTab(t)`（只返回HTML，不更新DOM）
- 正确：调用 `showTab(t)`（设置 `projectTab=t` → 调用 `renderProject()` 完全重渲染）
- 同理：子视图切换（如 assetsTab='global'）也必须调用 `renderProject()` 而不是 `rPTab()`
